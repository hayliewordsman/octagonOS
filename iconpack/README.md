# FacetUIIcons

FacetUI applied to every app icon on the device.

![The FacetUI icon set](../docs/preview/facetui-icons.png)

```bash
./build.sh              # generate, verify, and package
SKIP_APK=1 ./build.sh   # generate and verify only; no Android SDK needed
```

## How it covers everything

Two mechanisms, and the second is the one that makes the coverage total.

**Curated.** `glyphs.py` maps components to purpose-drawn FacetUI glyphs, and
`make-icons.py` renders them into an adaptive icon each. Good, but finite: it
only ever covers apps somebody has drawn a glyph for.

**Procedural.** Everything else is recomposed at load time by
[`patches/iconloader/0001`](../patches/iconloader/0001-facetui-icon-glass.patch):
the app's own artwork is lifted onto the same glass octagon the curated icons
use. Nothing has to be added to a list when a user installs something.

The recomposition builds a genuine `AdaptiveIconDrawable` rather than filtering
the finished icon, so masking, shadows and monochrome extraction all keep
working on it exactly as they would on an icon the app shipped that way. For an
app that already ships an adaptive icon, only its *foreground* is taken —
keeping its background would put a coloured square inside the octagon.

## What is in here

| Path | What it is |
|---|---|
| `glyphs.py` | Glyph path data, and the component map |
| `make-icons.py` | The generator |
| `FacetUIIcons/` | The pack: manifest, and generated `res/` |
| `build.sh` | Generate, verify, package |

`FacetUIIcons/res/` is **generated**. Run the generator; do not hand-edit it.

## One glass, two sources

The glass tile is a raster, generated by `make-icons.py` from FacetUI's own
shader maths — the same `facet_math.py` the boot animation uses. The glyphs
stay vectors, because a glyph is flat and should be crisp at any size.

That split is the design. The edge highlight and the rim darkening are
exponential falloffs and a vector drawable has no way to express them; a glyph
rendered as a raster would be soft at sizes the launcher actually asks for.

The engine loads the tile *from this pack* rather than generating its own, so a
curated icon and a procedurally themed one are the same asset and cannot drift
apart. With the pack absent the engine does nothing and icons are left stock —
there is no second, approximate glass to keep in sync.

## The shape

The pack does not draw the octagon's silhouette. It draws a tile that fills the
adaptive-icon mask, and the mask itself is set to a regular octagon by
`overlay/FacetUIFramework` — `config_icon_mask`, which `AdaptiveIconDrawable`
applies to **every** adaptive icon on the device.

So an app that ships its own adaptive icon and is not curated here still comes
out octagonal, even before the engine recomposes it.

## Adding an app

Add an entry to `APPS` in `glyphs.py`, pointing at an existing glyph or a new
one, then rebuild. A bare package matches any activity in it; a full
`package/activity` overrides its own package.

```python
"com.example.thing": ("files", HUE_MID),
```

Glyphs are authored as **outlines on a 100x100 viewport**, never as strokes: a
stroked path scales by line width and an outlined one does not. Overlapping
subpaths are XORed, not merged, because the fill is `evenOdd` — that is what
makes a gear's centre hole work, and it is why the sun is a disc with separate
rays rather than the obvious cloud of overlapping circles.

`tools/verify-iconpack.py` reports the worst glyph's distance from centre
against the safe zone on every build. Keep an eye on it: artwork that clears
this pack's octagon can still be clipped by a launcher using a tighter mask.
